# 技術スタック

fx_channel はサーバーとクライアントで技術を分けます。

## Backend Server

- Language: **Python 3.11+**
- API framework: **FastAPI**
- ASGI server: **Uvicorn**
- Config: **YAML / PyYAML**
- Protocol: HTTP/JSON
- Web frontend hosting: FastAPIからFlutter Webの静的成果物を配信可能

サーバーReleaseはPython環境を要求せず、自己完結バンドルとして配布します。

Pythonを選ぶ理由：

- 相場分析・統計・AI連携を追加しやすい
- 運営者がスキル実装を拡張しやすい
- FastAPIでUser APIとOperator APIを明確に分離しやすい

## Storage

標準: **SQLite**

- 追加DBサーバー不要
- `data/fx_channel.db` 1ファイル
- WALモード
- プレイヤーの取引・通貨・キャラ・スキル状態を永続化
- Operator Appからオンラインバックアップ生成可能

永続化層は `PlayerStateStore` 境界の後ろに置き、将来PostgreSQL等へ交換できるようにします。

## User App

- Language: **Dart**
- Framework: **Flutter**
- Targets:
  - Windows 10+ x64 → **EXE**
  - Android 9.0+ arm64-v8a → **APK**
  - Web → **Flutter Web**

同一のApplication層・APIクライアントを使い、Frontendだけ差し替え可能にします。

デフォルトFrontendは `jp_soft_pop`。

## Operator App

- Language: **Dart**
- Framework: **Flutter**
- User Appとは**別Flutterプロジェクト**
- 初期ターゲット:
  - Windows x64 → EXE
  - Linux x64
- Web版は必要になった場合に追加可能

Operator AppへUser AppのGUIコードや認証情報を混ぜません。

## Web版

User Appと同じFlutterコードからWebビルドします。

```text
clients/user_app
   ├─ Windows EXE
   ├─ Android APK
   └─ Flutter Web
```

サーバーバンドルへWebビルドを同梱した場合、

```text
https://example.com/play/
```

のようなURLから遊べる構成にできます。

Web版を使わない運営では `web-user/` を置かなければよく、必須ではありません。

## 境界

```text
Flutter User App ── User API ──┐
                               │
                         FastAPI Server
                               │
Flutter Operator App ─ Operator API ─┘
```

ゲームルール・FX計算・ガチャ抽選・スキル処理・相場処理はサーバー側です。

Flutter側は表示、入力、クライアント状態、API呼び出しに限定します。
