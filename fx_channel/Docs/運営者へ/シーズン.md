# シーズン運営

fx_channel のランキング競争はシーズン単位で区切れます。

標準設定：

```yaml
season:
  enabled: true
  duration_days: 7
  reset_balance: true
  keep_achievements: true
```

## 自動切替

シーズン開始時刻・終了時刻はサーバーのSQLiteへ保存されます。

`duration_days: 7` なら、開始から7日経過した後の最初のアクセス時に自動で次シーズンへ進みます。

サーバーを数日停止していても、再起動後に時刻を確認して必要なシーズン数だけ自動的に追いつきます。

時刻の正本はUTCです。ユーザーGUIでは端末のローカル時刻へ変換して表示します。

## reset_balance: true

標準はこちらです。

シーズンごとの取引状態を別namespaceへ保存します。

```text
trading:season-000001
trading:season-000002
trading:season-000003
...
```

新シーズンでは、

- ゲーム内FX残高を `game.starting_balance` から開始
- 前シーズンの未決済ポジションは新シーズンへ持ち越さない
- ランキング参加者を新しく集計

となります。

**前シーズンの取引データをSQLiteから削除するわけではありません。**

将来的な履歴表示・監査・集計に使えるよう、過去namespaceは残します。

## reset_balance: false

残高と未決済ポジションを次シーズンへ持ち越します。

ランキング参加者リスト自体は新シーズン用に分かれます。

長期的な資産差が残り続けるため、通常の競争運営では `true` を推奨します。

## シーズンを越えて保持するもの

標準実装では以下はシーズン切替で消えません。

- 所持キャラクター
- キャラクター重複数
- ガチャ通貨
- スキル状態・クールダウン
- User Session / Player ID

キャラ・石・スキルは取引残高とは別namespaceに保存されています。

`keep_achievements` は将来の実績システム用設定です。現時点では実績システム自体は未実装です。

## ランキング

ランキングは現在シーズンに参加したプレイヤーだけを対象にします。

参加とは、現在シーズン中にホーム・取引等の認証済みユーザー処理へアクセスすることです。

順位と評価額はサーバー側が計算します。クライアントから順位や資産額を自己申告する方式にはしません。

## 手動で次シーズンへ進める

運営アプリに **「次シーズンへ進める」** ボタンがあります。

実行前に確認ダイアログを表示します。

Operator APIでは：

```text
action: advance_season
```

として実行されます。

`reset_balance: true` の場合、その瞬間から新しい取引namespaceへ切り替わります。

イベント終了や緊急リセット等で利用できます。

## duration_days を変更した場合

運営設定のシーズン有効/無効や期間を変更してサーバーを再起動した場合、現在の古いスケジュールを途中で伸縮させず、**新しいシーズン番号で新しいスケジュールを開始**します。

運営途中で変更する場合は告知してから行うことを推奨します。

## バックアップ

シーズン状態も `fx_channel.db` に保存されています。

運営アプリのサーバーバックアップには、

- シーズン状態
- 各シーズンの取引状態
- 現在シーズン参加者
- キャラ・石・スキル
- User Session署名鍵

が含まれます。
