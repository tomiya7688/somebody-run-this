# キャラ・スキル・ガチャの追加方法

fx_channel のキャラクター、スキル、ガチャ排出テーブルは **ソースコードを書き換えずに YAML を追加して登録できる** 方針です。

運営者が主に触る場所は次です。

```text
fx_channel/content/
├─ characters/   # キャラクター
├─ skills/       # スキル
└─ gacha/        # ガチャ排出テーブル
```

---

# 最重要ルール：スキルは相場を動かせません

**キャラクターやスキルには、市場価格を書き換える権限を与えません。**

これは REAL 相場でも SIMULATED 相場でも同じです。

スキルが利用できるもの：

- 現在価格の読み取り
- 過去価格の読み取り
- プレイヤー自身の状態
- ゲーム内ニュースや公開済み情報
- 統計処理
- 予測モデル
- 外部AIや高度な推論機能（運営者が実装した場合）

スキルが利用できないもの：

- PriceProvider の価格変更
- SIMULATED 相場の乱数操作
- 次の価格を確定させる内部状態へのアクセス
- REAL 相場データの改ざん
- 特定プレイヤーだけ有利になるような価格配信

つまり「未来予知」「先読み」「相場予測」という名前のスキルであっても、実際には **公開済みデータを材料に予測結果を返すだけ** です。

## 予測は保証ではありません

たとえば先読みスキルが、

```text
USDJPY
上昇予想: 63%
下降予想: 37%
信頼度: 中
```

と表示しても、それは予測です。

**次の値動きを保証するものではありません。**

高度な推論、統計モデル、LLM、機械学習などを利用しても、必ず当たる仕様にはしません。

# キャラクターを追加する

`content/characters/` に YAML を1ファイル追加します。

例：

```yaml
id: analyst_mika
name: ミカ
rarity: SSR

description: マーケット分析が得意なアナリスト。

skills:
  - trend_reader
  - volatility_alert

tags:
  - analyst
  - beginner_friendly
```

### id

内部IDです。

- 半角英数字と `_` を推奨
- 一度公開したIDはなるべく変更しない
- 他キャラクターと重複させない

### name

ゲーム内表示名です。

### rarity

任意のレアリティ文字列です。

例：

- N
- R
- SR
- SSR

レアリティそのものに特別なゲームロジックはありません。

### skills

このキャラクターが持つスキルIDです。

`content/skills/` に存在するIDだけ指定できます。

# スキルを追加する

`content/skills/` に YAML を追加します。

例：

```yaml
id: trend_reader
name: トレンドリーダー
type: forecast

description: 直近の値動きから短期方向を推測する。

implementation: trend_reader_v1

cooldown_seconds: 300

parameters:
  lookback_ticks: 120
  horizon_ticks: 12
```

### type

スキルの大分類です。

初期方針：

- `forecast` — 将来方向・変動幅などを予測して表示
- `analysis` — 現在や過去の相場を分析して表示
- `alert` — 条件成立時に通知
- `utility` — UIや取引補助など、市場価格を変更しない機能
- `passive` — 常時有効な表示・分析補助

### implementation

実際に処理を行う実装IDです。

YAML側は実装名を指定するだけにし、コード側のスキル実装レジストリから呼び出します。

**implementation から市場価格を書き換えるAPIは提供しません。**

### parameters

スキルごとの設定値です。

同じ実装でもパラメータを変えて別スキルとして登録できます。

# ガチャを追加する

`content/gacha/` に YAML を追加します。

例：

```yaml
id: standard_character
name: スタンダードキャラガチャ

currency: premium_gem
cost: 300

entries:
  - character: analyst_mika
    weight: 5
  - character: rookie_aki
    weight: 95
```

`weight` は相対重みです。

上の例なら、

- analyst_mika: 5%
- rookie_aki: 95%

になります。

合計を100にする必要はありません。

# 課金とガチャについて

標準実装では、ガチャから得られるキャラクターやスキルによって **市場そのものを操作できない** ようにします。

課金要素として有料ガチャを運営する場合は、運営地域の法令・プラットフォーム規約に従い、

- 排出確率の表示
- 購入価格の表示
- 年齢に応じた制限
- 購入上限や返金ルール
- 有償通貨・無償通貨の扱い

などを運営者側で確認してください。

fx_channel 側ではゲーム内残高やガチャ報酬を現金へ換金する機能は提供しません。

# 設計上の境界

スキル処理は概念的に次の位置に置きます。

```text
                    ┌─────────────────────┐
REAL API ────────→  │                     │
                    │    PriceProvider    │ ─────→ MarketSnapshot
SIMULATED Engine →  │                     │
                    └─────────────────────┘
                                                │
                                                │ 読み取り専用
                                                ▼
                                      ┌──────────────────┐
                                      │   Skill Engine   │
                                      └──────────────────┘
                                                │
                                                ▼
                                      予測・分析・通知結果
```

**Skill Engine から PriceProvider へ戻る矢印は作りません。**

これを fx_channel の基本ルールとします。
