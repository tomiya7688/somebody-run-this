# サーバー設置 — 展開して置くだけで運営する

fx_channel サーバーの正式な運営導線は、

> **Releaseから自分のOS/CPU用バンドルを取る → 展開 → 設定ファイルを作る → 起動**

です。

Pythonや開発環境をサーバーへ入れることを前提にしません。

## 配布予定バンドル

```text
fx-channel-server-linux-x64.tar.gz
fx-channel-server-linux-arm64.tar.gz
fx-channel-server-windows-x64.zip
```

各バンドルの中には最低限、次を含めます。

```text
fx-channel-server/
├─ fx-channel-server        # Linux
│  または
├─ fx-channel-server.exe    # Windows
├─ config/
│  └─ operator.example.yaml
├─ content/
│  ├─ characters/
│  ├─ skills/
│  └─ gacha/
├─ start-server.sh          # Linux
├─ start-server.ps1         # Windows版
└─ README-FIRST.md
```

## 対応する一般的なサーバー

### Linux x64

主対象：

- Ubuntu Server
- Debian
- 一般的なglibc系Linux VPS

よくあるx64 VPSなら最初に選ぶ配布物です。

### Linux ARM64

主対象：

- Ubuntu Server ARM64
- Debian ARM64
- ARM系クラウドVM

### Windows x64

主対象：

- Windows Server
- 小規模運営用のWindows 10/11 x64

Windows Serverでも、Linuxサーバーとゲームロジックは同じです。

# 初回起動

## Linux

```bash
cp config/operator.example.yaml config/operator.yaml
export FX_CHANNEL_OPERATOR_TOKEN="十分に長いランダムな値"
chmod +x fx-channel-server start-server.sh
./start-server.sh
```

## Windows Server

PowerShell：

```powershell
Copy-Item config\operator.example.yaml config\operator.yaml
$env:FX_CHANNEL_OPERATOR_TOKEN = "十分に長いランダムな値"
.\start-server.ps1
```

運営用トークンを恒久設定する場合は、OSのSecret管理・サービス設定・安全な環境変数管理を利用してください。

# データ保存とバックアップ

標準構成は **SQLite** です。

```text
data/
├─ fx_channel.db
└─ user_session_secret.bin
```

- `fx_channel.db`: ポジション、ゲーム内通貨、所持キャラ、スキルクールダウン等
- `user_session_secret.bin`: 匿名ユーザーセッションを同じPlayer IDへ戻すための署名鍵

**復元には両方が必要です。**

運営アプリの「サーバー状態をバックアップ」を実行すると、SQLiteのオンラインバックアップAPIを使って、

```text
backups/fx_channel-backup-YYYYMMDD-HHMMSS.zip
```

を作成します。ZIPにはDBと署名鍵が入ります。

このZIPはユーザー向けWeb/APIから配信しません。SSH、RDP、VPS管理画面等のサーバー管理経路から安全な場所へコピーしてください。

署名鍵は秘密情報です。バックアップZIPも公開しないでください。

標準SQLite構成は単一サーバープロセス向けです。将来、複数サーバーへ水平分割する規模では外部DBアダプターへ切り替える方針です。

# 必要スペックと回線の目安

以下は **ベンチマーク前の初期設計目安** です。保証値ではありません。

実際の必要量は、

- 同時接続数
- 価格更新頻度
- チャート履歴量
- DB
- ログ保存期間
- スキル分析の重さ
- AI/LLMをサーバー内で実行するか
- リアル相場APIへのアクセス方式

によって変わります。

| 想定同時接続 | CPU | RAM | 空きストレージ | 推奨上り帯域 |
|---:|---:|---:|---:|---:|
| 〜50人 | 2 vCPU | 2 GB | 10 GB+ | 10 Mbps+ |
| 〜200人 | 2〜4 vCPU | 4 GB | 20 GB+ | 25 Mbps+ |
| 〜500人 | 4 vCPU | 8 GB | 30 GB+ | 50 Mbps+ |
| 〜2,000人 | 8 vCPU | 16 GB | 50 GB+ | 200 Mbps+ |

### これはかなり余裕を持たせた初期値

FXチャートや価格配信は更新頻度によって通信量が大きく変わります。

Release前に負荷試験を追加し、実測結果が取れたらこの表を更新します。

### AIスキルについて

高度な推論をローカルGPUで実行する場合は、上表とは別にGPU/VRAM要件が発生します。

外部AI APIを使う場合はサーバーGPUは不要ですが、API料金・レート制限・タイムアウトを運営者が設定する必要があります。

**AIスキルを使わない通常運営ではGPU必須にしません。**

# ネットワーク

公開運営時の推奨：

- サーバー自体はプライベートな管理面を保つ
- User APIはHTTPSで公開
- Operator APIは可能ならIP制限/VPN等も併用
- 運営トークンをユーザーアプリへ含めない
- 80/443以外の内部ポートを直接公開しない構成を推奨

標準サーバーの内部待受ポートは設定で変更可能です。

---

# 「置くだけ」を壊さないルール

サーバー機能追加時は以下を守ります。

1. Pythonの手動インストールを必須にしない
2. Node.js等の別ランタイムを運営者へ追加要求しない
3. DBは初期小規模構成を同梱/自動生成できる方式を優先
4. 外部DBが必要になる場合も設定で切替可能にする
5. 設定は `config/operator.yaml` と環境変数へ集約
6. バイナリの置換だけでアップデートできる構造を維持
7. Linux x64 / Linux arm64 / Windows x64 のRelease成果物を維持

「ソースをcloneして環境構築しないと運営できない」は正式運営手順にしません。
